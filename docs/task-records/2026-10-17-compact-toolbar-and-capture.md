# Compact toolbar and native capture recovery

The customer retest found that the narrow toolbar hid History, Site checks, and Help. An initial recovery menu exposed those actions at 600px, but the native 390px check then showed Publish outside the viewport. The final compact layout applies below 768px: device switches, Preview, More tools, and Publish remain visible; the menu delegates to the original Undo, Redo, panel toggle, checks, history, review, live-link, and help actions. It refreshes labels, permission visibility, and disabled states from those controls.

Native local acceptance covers 320, 390, 600, 601, and 768px. All five have exact viewport/scroll width and contained Preview, device, and Publish controls. The 390px flow exercises the panel toggle, checks, history, help, client-review dialog, focus return, and a real Add heading → Undo → Redo → Undo round trip. Preview switches render 414px Mobile, 834px Tablet, and available-width Desktop; Mobile scales to fit a 390px browser without overflow. WordPress package acceptance is recorded separately.

The canonical validator requires the new recipe and retains its other provenance checks and existing pixel thresholds.

All captures use the direct screenshot path, with matching sources, capture code, environment, and recipe.
