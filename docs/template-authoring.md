# Private native template authoring

The hosted `/mcp/template-authoring` resource creates unpublished template drafts. It cannot promote packages, publish customer sites, modify released templates or use existing assistant/import credentials. Enable it explicitly with `PAGECRAFT_TEMPLATE_AUTHORING=1` and an exact comma-separated `PAGECRAFT_TEMPLATE_AUTHOR_IDS` allowlist of authenticated principal IDs: `authUserId` for Supabase-backed users, otherwise the Pagecraft profile ID. Keep staging workers disabled and the staging publication directory separate from production.

An allowed signed-in operator can open `/owner/template-drafts`, create or revoke an authoring credential at `/owner/template-drafts/access`, and open the same drafts in the native builder. Credentials are audience- and environment-bound, stored as hashes and revocable. Treat the one-time raw credential as a secret. Never place it in source, evidence, logs or a public URL.

The MCP tools list/create/read drafts, discover supported native controls and defaults, save with expected revision, upload images, validate through the portable-package pipeline and export one exact immutable revision. Read the returned revision after every upload/save. A stale revision fails with a conflict; read the draft again before retrying. Authoring validates native document/schema fields, supported controls, safe content/URLs and referenced image assets. Executable code and unsupported content are rejected.

Drafts, immutable revision JSON, images and grants live in the environment's private publication root under `.template-authoring/<environment>`. Grants are in that environment directory's `.grants` child. Release-directory switches do not replace this storage. File writes use temporary files, sync, atomic linking/rename and cross-process locks. A killed mutation owner can be recovered on the next mutation without losing acknowledged revisions. Native editor saves use the same validation and revision store as MCP. Uploads advance revision and are serialized against editor saves.

The default storage limit is 512 MiB per draft. It includes immutable revision files and complete content-addressed images, including unreferenced images retained after interrupted writes. Temporary UUID files are removed under lock on the next mutation. There is no global account-wide budget or automatic deletion of retained complete blobs. Operators must monitor hosting capacity. Catalog promotion and immutable release storage remain outside this resource.

If a process dies while holding a `.recovery` guard, recovery fails closed. Stop all workers sharing that environment/root, verify that no worker holds or can acquire the lock, back up the private root, inspect the recorded owner PID and confirm it is dead. Only then remove the stale `.recovery` directory and any confirmed-dead `.lock`. Restart and verify revision history and grant/revocation state. Investigate PID reuse or ambiguous ownership; never remove an active lock.

Preview links require the allowed operator session and are bound to a revision. Draft previews block form submission. Export responses include revision, package SHA-256 and a credential-protected download URL. The versioned declarative source tooling can import that package with `npm run template -- import-draft`; exact package/document/asset/provenance parity is checked before draft source files are retained. Existing TypeScript factory sources remain supported. Package compatibility still requires actual Cloud and WordPress fresh-import/edit/save/reopen/reimport verification.

Keep design, image, complete-site and exact-package approvals separate. A private draft or successful validation is not catalog approval. Production activation remains a separate release decision.
